# 회의 결과 개조식 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 네 출력 형식의 회의 결과를 `{ text, details }` 항목(하위 항목 한 단계)으로 받고, 두 앱의 화면·복사·파일이 목록·하위 목록으로 보이게 함, 옛 결과는 파일을 고치지 않고 읽을 때만 바꿈

**Architecture:** 항목 규칙(변환·빈 값 정리·목록 줄 만들기·길이 계산)을 `출력형식.js` 한 곳에 두고 Windows 서버·Windows 화면·휴대폰 화면이 함께 씀, 휴대폰 네이티브는 같은 규칙의 Java 판(`MinutesItems.java`)을 두고 두 언어가 공통 예시로 같은 결과를 냄, 서버는 AI 응답(새 구조만, 엄격)과 저장 결과(옛·새 허용) 검사를 나눔

**Tech Stack:** Node.js(번들 서버 `서버.cjs`, zod 묶음 `external_exports`), 브라우저 JS(WebView2·Android WebView), Java(Android, org.json), `node:test`, 헤드리스 화면 검사, Android 기기 시험(`AndroidChecks`)

**Spec:** `작업기록/2026-11-16-개조식회의록/설계/2026-11-16-회의결과-개조식-설계.md`(사용자 승인 "이어서 작업 진행해줘 그냥", 2026-11-16)

## Global Constraints

- 하위 항목은 한 단계만, 항목 하나 — `{ "text": 문자열, "details": 문자열 배열 }`
- AI 응답 한도 — `text` 1~1000자, `details` 0~8개 각 1~1000자, `overview` 최대 12개, 주제 최대 30개·주제마다 항목 최대 30개, `decisions`·`openQuestions` 최대 40개
- `actions`(`task`·`owner`·`due`)와 `suggestedTitle` 구조는 바꾸지 않음
- 응답 JSON 64,000자 한도(`AI_OUTPUT_LIMIT`)와 재전송 입력 64,000자 제한은 그대로
- 저장 원본(`minutes`)은 어디서도 바꾸지 않음 — 변환은 화면 그리기·글 만들기·AI 재전송 바로 앞에서만
- 옛 결과 바꾸기 규칙 — 설계 「옛 결과 바꾸기 규칙」 그대로(알려진 머리말 넷 `전체 방향`·`주요 결정`·`다음 할 일`·`남은 쟁점`, 첫 ` | `에서만 나눔, 앞 글머리표 묶음 떼기, 공백만 있는 글은 빈 글, 자르지 않음)
- 빈 값 정리 — 빈 `details` 글 버림, `text`가 비면 첫 `details`를 올림, 둘 다 비면 항목 버림
- 절 순서와 제목은 형식·앱마다 지금 그대로
- 목록 기호 — md·txt·휴대폰 복사 `- 본문`, Windows 위쪽 복사·공유·텍스트 파일 `• 본문`, 하위 항목은 모든 경로 `  - 하위`, 여러 줄 본문의 이어지는 줄은 본문과 같은 깊이로 들여 씀
- `desktop/앱/출력형식.js`와 `mobile/안드로이드/assets/formats.js`는 바이트가 같아야 함
- `CustomFormat.java`의 `instruction()`은 `customInstruction()`과 글자 하나까지 같아야 함
- 새 소스 파일 첫 줄은 역할을 적은 한국어 한 줄, 설명 주석은 설명 대상 코드 바로 아래
- 화면 글·안내는 한국어, 「판」 대신 「버전」
- 데스크톱 시험은 `VN_PLAYWRIGHT=없음`(설정브라우저 시험 1개 건너뜀이 정상), Playwright는 쓰지 않음, 화면 확인은 이고라이트와 저장소 헤드리스 검사
- 실제 OpenAI는 Task 8에서 합성 전사로만, 키는 대화로 받지 않음
- 가상기기는 설치 전에 옛 앱 삭제, 설치 출력 `Success` 확인, 끝나면 가상기기·adb 끔

## Review Focus

- 2000자 문단·빈 문자열·13줄 넘는 overview를 가진 옛 회의 → 열리고 잘림 없이 보이고 저장됨 → Task 2 저장 검사 시험, Task 4 공통 예시, Task 5·7 화면 시험
- AI가 옛 문자열 구조로 답함 → 응답 형식 오류로 끝나고 저장되지 않음 → Task 2 시험
- 일본어·중국어 글자 정리로 `text`·`details`가 비게 됨 → 빈 값 정리 규칙대로 남음 → Task 1 공통 예시, Task 2 서버 시험, Task 6 Java 시험
- 여러 줄 옛 문단 → 항목 하나, 이어지는 줄이 하위 항목처럼 보이지 않음 → Task 1 `itemLines` 예시, Task 4 공통 예시, Task 5 복사 시험
- 결과 줄이기에서 `details`만 줄어든 답·머리말만 남은 답 → 앞의 것은 받고 뒤의 것은 거절, JS·Java 같음 → Task 2·Task 6 시험
