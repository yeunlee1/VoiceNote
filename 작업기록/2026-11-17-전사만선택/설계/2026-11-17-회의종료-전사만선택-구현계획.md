# 회의 종료 '전사까지만' 고르기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 회의 종료·녹음 파일 불러오기 때 '회의록까지 만들기'와 '전사까지만'을 고르고, 전사만 저장한 회의는 정리본 탭의 '회의록 만들기'로 이어서 만든다(Windows·휴대폰).

**Architecture:** 두 앱 모두 분석 시작 직전에 같은 문구의 작은 창으로 방식(`minutes`·`transcript`)을 고른다. Windows는 화면(`app.js`)이 전사만 요청하고 기존 전사 저장 경로에 보관한다. 휴대폰은 화면이 녹음 정지·저장(`finish` hold)과 분석(`analyze` mode)을 나눠 부르고, 서비스가 `Ai.transcribeOnly`로 전사만 한 뒤 상태 `transcribed`를 남긴다.

**Tech Stack:** Windows — Node 로컬 서버(`회의보관.cjs`)와 순수 HTML·CSS·JS 화면. 휴대폰 — Java 서비스·org.json, 웹뷰 HTML·CSS·JS. 시험 — `node --test`, JVM 단독 시험, 헤드리스 Chrome 화면 검사, 가상기기 `AndroidChecks`.

**Spec:** `작업기록/2026-11-17-전사만선택/설계/2026-11-17-회의종료-전사만선택-설계.md`

## Global Constraints

- 방식 값은 `minutes`(회의록까지, 기본)와 `transcript`(전사까지만) 두 가지만 씀, 휴대폰 상태 값은 `transcribed`
- 화면 문구(두 앱 같음)
  - 창 제목 「회의록을 어디까지 만들까요?」
  - 단추 「회의록까지 만들기」 — 설명 「전사한 뒤 회의록으로 정리합니다.」
  - 단추 「전사까지만」 — 설명 「전사문만 저장합니다. 회의록은 나중에 정리본 탭에서 만들 수 있습니다.」
  - 닫기 단추 「닫기」
  - 창 안내 — 종료·저장 뒤 「음성은 저장했습니다.」, 휴대폰 불러오기 「녹음 파일을 고르기 전에 어디까지 만들지 정합니다.」, 음성만 있는 회의 다시 분석 「저장된 음성으로 만듭니다.」
  - 목록 꼬리표 「전사만」
  - 정리본 탭 안내 「전사만 저장한 회의입니다. 전사문은 옆 ‘전사문’ 탭에 있습니다.」, 단추 「회의록 만들기」
  - 전사만 끝 — Windows 안내 「전사를 저장했습니다. 회의록이 필요하면 정리본 탭의 ‘회의록 만들기’를 누르세요.」, 휴대폰 상태 문구 「전사 저장 완료 · 회의록이 필요하면 정리본 탭의 ‘회의록 만들기’를 누르세요.」
  - 창을 닫았을 때 — Windows 「음성은 저장했습니다. 회의록이나 전사가 필요하면 ‘저장·분석 다시 시도’를 누르세요.」, 휴대폰 「음성을 저장했습니다. 회의 기록에서 열어 분석할 수 있습니다.」
- 창의 처음 초점은 「회의록까지 만들기」, 기억 기능 없음(사용자 결정 2026-11-17)
- 체험(공용 기본 키 3회) — 전사까지만도 분석 1회로 확정(Windows `settleTrial("finish")`, 휴대폰 `finishAccess`), 실패면 예약 반환
- 휴대폰 알림의 '회의 종료 · 분석'은 지금처럼 회의록까지(창 없음)
- 한 회의에서 고른 방식은 그 회의를 연 동안 기억함(Windows `state.finishMode`, 휴대폰 `state.finishMode`) — 실패 뒤 다시 시도는 같은 방식으로 이어 가고 창을 다시 띄우지 않음, 창을 닫았거나 아직 고르지 않았으면 전사할 음성이 있을 때 창을 띄움, 새 회의·다른 회의 열기·불러오기에서 지움(짝보고-1 꼭 고칠 것 1)
- 휴대폰 `analyze` 요청에도 시도 번호(`attemptId`)를 실어 화면이 그 시도의 끝 상태(`complete`·`failed`·`transcribed`)로 결과를 열고 끝 문구를 냄 — 의견 반영·불러오기와 같은 방식(짝보고-1 꼭 고칠 것 3)
- 실제 OpenAI 호출 없음, 데스크톱 시험은 `VN_PLAYWRIGHT=없음`
- `출력형식.js`·`formats.js`·AI 지시·회의록 형식은 바꾸지 않음
- 대화상자는 각 앱의 기존 양식을 씀 — Windows `dialog.modal`(modal-head·modal-body·button-row), 휴대폰 `dialog > .modal`
