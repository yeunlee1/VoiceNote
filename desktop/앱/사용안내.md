# VoiceNote

프로젝트를 고른 뒤 **회의 준비 → 회의 시작 → 회의 종료** 순서로 사용합니다. 종료하면 음성을 이 PC에 먼저 저장하고, AI 전사와 요약을 진행한 뒤 프로젝트에 회의록을 보관합니다.

별도 DB·Node 설치는 필요 없습니다. Windows 10(버전 2004 이상) 또는 11의 x64 환경에서 독립 프로그램 창으로 실행됩니다. 자동 분석에는 인터넷과 사용 가능한 OpenAI API 키가 필요합니다. ChatGPT 구독과 API 사용료는 별개입니다.

## 처음 실행

1. `VoiceNote-1.2.0-설치.exe`를 실행해 설치하고 바탕화면의 `VoiceNote` 아이콘을 엽니다. 이전 버전의 `VoiceNote 회의 기록` 바로가기는 새 `VoiceNote` 바로가기로 바뀝니다. 설치 파일명 앞에 배포 날짜가 붙을 수 있습니다. 이전 `프로젝트 회의록` 설치본 위에 설치하면 같은 위치를 갱신하고 회의 자료는 그대로 둡니다. WebView2가 없으면 설치 중 인터넷으로 준비합니다.
2. 화면 오른쪽 위 `AI 설정`을 눌러 API 키를 입력하고 `키 등록·변경`을 누릅니다. 개인 노트북에서는 `이 PC에 키 저장`으로 다음 실행에도 사용할 수 있습니다. 같은 창에서 키 삭제와 요약 모델 선택도 합니다. 입력한 키는 화면에 다시 표시하지 않습니다. 공개 소스의 기본 빌드에는 체험용 기본 키가 없으므로, 분석하려면 자신의 OpenAI API 키를 먼저 등록해야 합니다.
3. 왼쪽 목록에서 프로젝트를 고릅니다. 새로 설치하면 빈 프로젝트 1개로 시작하고, `+ 프로젝트 추가`로 최대 3개까지 늘립니다. 회의 기록이 없는 프로젝트는 `회의 준비`의 `프로젝트 삭제`로 지울 수 있습니다. 이전 버전에서 저장한 1~3번 설정은 업데이트한 뒤에도 그대로 남고, 4~9번은 화면에 보이지 않지만 파일은 지우지 않습니다. 따로 받은 프로젝트 설정 파일이 있으면 `설정 불러오기`로 넣습니다.
4. `회의 준비`를 누르면 프로젝트 이름, 회의명, 날짜, 출력 형식, 참석자, 상세 회의내용 입력칸이 열립니다. 키나 동의가 없어도 열립니다. 프로젝트 설명과 정리 기준은 `프로젝트 설명과 회의 정리 기준 (프리셋)`을 펼쳐 고칩니다.
5. `회의 준비` 바로 아래의 녹음 동의와 외부 AI 분석 동의를 체크합니다. 날짜·참석자·상세 회의내용은 회의마다 입력합니다.

## 회의 진행

- **회의 시작**은 API 키, 프로젝트 이름, 회의명, 두 동의가 모두 갖춰지면 바로 눌러집니다. 부족한 항목은 버튼 아래에 목록으로 표시됩니다. 시작할 때 바뀐 프리셋을 자동 저장합니다.
- **상세 회의내용**은 이번 회의의 안건·배경 메모입니다. 회의 기록에 함께 저장되고 다시 열 때 복원되며, 요약 요청에는 사전 참고 자료로만 전달됩니다. 회의록 내보내기 파일에는 넣지 않습니다.
- 처음 녹음할 때 마이크 사용을 허용합니다. 처음에는 20~30초 시험 녹음을 하고 재생해 실제 자리의 목소리가 들리는지 확인하세요.
- 녹음 중에는 시작 버튼 자리에 **회의 종료**가 나타납니다. 녹음 중에는 프로젝트·회의 정보·AI 설정을 바꿀 수 없습니다. 회의 종료를 누르면 녹음을 마무리하고 모든 원음 파일을 저장합니다. 원음 저장을 확인한 뒤 전사·요약을 자동 실행합니다. ‘회의록 저장 완료’가 표시되면 프로젝트별 지난 회의 목록에 남습니다.

`마이크 음량 100% 설정`은 Windows 기본 입력 마이크의 음량을 100%로 설정하고 음소거를 해제합니다. 브라우저에서도 같은 마이크를 선택하세요. 설정은 도구를 종료해도 유지되며 스피커 음량과 마이크 부스트는 바꾸지 않습니다. 소리가 찢어지면 Windows 입력 음량을 낮추세요.

긴 회의는 파일당 약 59분 또는 22MB에 가까워질 때 다음 파일로 이어집니다. 종료할 때 모든 파일을 순서대로 저장하고 분석합니다. 녹음 중에는 아직 디스크에 저장되지 않았으므로 새로고침·탭 종료·절전을 피하세요. 마이크가 분리되면 녹음이 중단될 수 있습니다.

## 프로젝트와 보관 자료

`%LOCALAPPDATA%\MeetingJournal\회의자료\프로젝트-01`부터 `프로젝트-03`에 자료가 저장됩니다. 내 형식은 같은 폴더의 `내형식.json`에 저장됩니다. 화면의 `회의자료 폴더 열기`로 확인할 수 있습니다. 설치 폴더와 분리되어 프로그램 업데이트나 제거 후에도 회의 자료는 보존됩니다.

- `설정.json`은 프로젝트 이름·회의명·배경과 정리 기준입니다.
- `원음-…webm` 등의 파일은 녹음입니다. 브라우저에 따라 m4a 또는 wav가 될 수 있습니다.
- `녹음-…json`은 회의 정보와 원음 파일 목록입니다.
- `전사-…txt`는 요약 전에 저장한 전사 원문입니다. 요약에 실패해도 지난 회의에서 다시 불러와 사용할 수 있습니다.
- `회의-…json`은 복원용 내부 자료로 전사 원문·회의록·당시 프로젝트 이름을 보관합니다. `회의-…md`와 화면의 TXT·Markdown·JSON 다운로드에는 회의록만 담고 전사와 사전 배경은 제외합니다.

왼쪽 지난 회의를 누르면 회의 결과 창이 열립니다. 위쪽 `정리본`·`전사문` 탭으로 정리된 내용과 녹음에서 인식한 글을 바로 보고, 보고 있는 탭의 내용을 `복사`하거나 `텍스트 파일로 저장`해 메신저·메일로 공유합니다. 모델별 AI 사용량과 Markdown·JSON 저장은 `AI 사용량 · 다른 형식으로 저장`을, 전사 수정과 다시 분석은 전사문 탭의 `전사 고치기 · 다시 분석`을 펼쳐 씁니다. 새 회의를 하려면 `회의 준비`를 누르세요. 입력을 바꿔 다시 분석하면 기존 기록을 덮어쓰지 않고 새 결과를 보관합니다. 프로젝트 이름을 바꿔도 같은 번호의 기존 회의 기록은 남습니다. 새로운 별개 프로젝트에는 빈 번호를 사용하세요.

## 프로젝트 설정 파일

왼쪽 프로젝트 목록 아래 `설정 내보내기`는 저장된 프로젝트(최대 3개)의 이름·회의명·설명을 JSON 파일 하나로 내려받습니다. 이전 버전과 주고받을 수 있도록 파일은 9칸 형식을 유지하고 4~9번은 비워 둡니다. 내 형식은 넣지 않습니다. API 키, 체험 횟수, 요약 모델 선택, 회의·녹음·사용량은 넣지 않습니다. 화면에서 바꾸고 저장하지 않은 입력은 파일에 들어가지 않으므로 먼저 `프리셋 저장`을 누르세요.

`설정 불러오기`로 파일을 고르면 번호별 이름을 먼저 보여 줍니다. `설정 교체`를 누르면 프로젝트 설정 전체를 파일 내용으로 바꾸고, 취소하면 아무것도 바뀌지 않습니다. 4~9번에 내용이 있는 이전 버전 파일은 3개 제한 때문에 불러오지 않습니다. 저장된 회의와 녹음은 지우지 않습니다. 형식이 틀리거나 번호가 빠지거나 겹치는 파일, 128KiB를 넘는 파일은 하나도 바꾸지 않고 거절합니다. 녹음·분석 중에는 내보내기와 불러오기를 할 수 없습니다.

다른 PC로 옮길 때는 프로그램을 설치한 뒤 **회의자료 폴더**를 같은 사용자 자료 위치에 복사합니다. 기존 ZIP 버전의 기록도 프로그램을 종료한 상태에서 옮길 수 있습니다. 대상에 이미 기록이 있으면 덮어쓰지 말고 폴더를 먼저 보관하세요. API 키는 새 PC에서 다시 입력합니다. ‘현재 화면 비우기’는 보관 파일을 삭제하지 않습니다. 프로젝트 자료는 여러 PC 사이에 자동으로 동기화되지 않습니다.

## 저장이나 분석이 실패했을 때

- 음성 저장이 실패하면 분석을 시작하지 않습니다. 창을 닫지 말고 디스크 공간과 폴더 쓰기 권한을 확인한 뒤 ‘저장·분석 다시 시도’를 누르세요.
- 음성 저장 후 분석이 실패하면 원음은 남습니다. 앱을 다시 실행해 ‘분석 대기’ 회의를 열고 API 키와 전송 동의를 확인한 뒤 다시 분석할 수 있습니다.
- 일부 원음만 저장된 회의는 원래 녹음 창에서 나머지 저장을 완료해야 합니다. 이미 닫은 창의 미저장 음성은 복구할 수 없습니다.
- 회의록만 저장하지 못했다면 ‘프로젝트 저장 다시 시도’를 사용합니다. 이 동작은 AI를 다시 호출하지 않습니다.
- 실패한 AI 호출에도 비용이 발생했을 수 있습니다. 길이 한도에 걸리면 구간을 나눠 최대 6회 추가 요청합니다. 잔액·사용량·통신 오류에는 자동 재시도하지 않습니다. ‘다시 분석’에도 비용이 발생할 수 있습니다.
- 인식된 사람 이름·품목 코드·수치·부정 표현과 담당자·기한을 확인하세요. 녹취에 없는 내용은 만들지 않도록 요청하지만 결과는 검토가 필요한 초안입니다.

1.0.1부터 전사 원문은 요약 전에 자동 보관합니다. 회의 결과 창의 전사문 탭에서 ‘전사 고치기 · 다시 분석’을 펼치면 ‘전사 원문 저장’으로 직접 내려받을 수도 있습니다. 이전 버전에서 실패한 회의의 텍스트를 복사했다면, 해당 지난 회의를 열어 전사 칸에 붙여넣고 ‘입력한 전사로 다시 분석’을 누르세요. 이 버튼은 입력한 글을 사용하므로 음성을 다시 전사하지 않습니다.

요약 모델은 `AI 설정`에서 GPT-6.1 Sol(기본), GPT-6 Luna, GPT-6 Astra 중에 고릅니다. 1.2.0에서 GPT-6 Sol과 GPT-5.6 Terra는 목록에서 빠졌고, 이 두 모델을 저장해 둔 경우 AI 설정에서 모델을 한 번 다시 고르면 됩니다. medium 추론 강도와 요청당 출력 상한은 서버가 정합니다. 회의 기록 창의 ‘AI 사용량 · 이 회의 누적’에는 API가 알려준 입력·출력·합계 토큰을 실제 응답 모델별로 표시하고, 사용량을 받지 못한 요청은 0이 아니라 미제공으로 표시합니다. 같은 회의를 다시 분석하면 실패한 요청을 포함해 앞선 사용량에 이어서 더합니다. 다시 분석한 결과는 새 기록으로 저장되며 이전 결과와 그때의 사용량 기록은 지난 회의 목록에 남습니다. 새 회의를 준비하거나 녹음을 시작하면 사용량은 0부터 다시 셉니다. 핵심과 이유를 문장으로 설명하고 합의·제안·미확정 사항을 구분하도록 요청합니다. 긴 전사는 최대 24,000자씩 나눠 앞 구간의 회의록과 함께 처리합니다. 출력 상한은 입력 글자 수 제한이나 확정 과금량이 아닙니다. 길이 한도에 도달한 구간은 더 작게 나눠 최대 6회 추가 요청합니다. 분당 처리량 제한이나 계정 잔액·지출 한도는 자동 분할로 해결하지 않습니다. API 응답에 요청 ID가 있으면 오류에 함께 표시합니다.

## 출력 형식

`회의 준비`의 출력 형식에서 회의록·핵심 요약·업무 정리·내 형식 중 하나를 회의마다 고릅니다. 프로젝트별로 마지막에 고른 형식을 기억하고, 회의 기록에도 함께 남아 다시 열거나 다시 분석할 때 같은 형식을 씁니다. `예시 보기`를 누르면 고른 형식으로 정리한 예시가 나옵니다. 내 형식은 하나만 만들 수 있고, 넣을 항목·순서·항목 이름과 AI에게 줄 추가 지시를 정해 저장하거나 삭제합니다. 이미 저장된 회의는 당시 내 형식 정의대로 보여 줍니다. 핵심 요약은 전체 흐름과 주제별 요지를, 업무 정리는 할 일·담당·기한과 미확정 항목을 중심으로 보여 줍니다. 어느 형식이든 전사에 없는 발언·담당·기한은 만들지 않도록 요청합니다. 이전 기록은 회의록 형식으로 열립니다.

## 회의 제목과 날짜별 기록

AI가 회의 내용에 맞춰 제목을 정하고, 지난 회의 목록에는 날짜·그날의 차수·제목을 표시합니다. 차수는 프리셋과 날짜마다 1차부터 매깁니다. 같은 녹음의 재분석은 같은 차수를 유지하고 최신 결과를 목록에 표시합니다. 이전 결과 파일도 보존합니다.

전사는 분석 전에 저장합니다. 분석이 끝나면 날짜·차수·제목으로 구분되는 전사 TXT, 회의록 TXT, 요약 JSON을 프리셋 폴더에 따로 보관합니다. 회의록에는 전사를 붙이지 않습니다. 상단에는 전체 방향·주요 결정·다음 할 일·남은 쟁점을 요약하고 아래에는 상세 설명을 표시합니다.

자동 분할 추가 요청 상한에 도달하면 전사를 유지하고 중단합니다. 성공 구간 재사용은 같은 화면에서 재시도할 때 적용되며, 프로그램을 닫으면 처리 중 캐시는 사라집니다. 저장된 전사는 재실행 후 다시 불러와 분석할 수 있습니다.

## 키와 참고 자료

키 저장을 선택하면 `%LOCALAPPDATA%\MeetingJournal\.env.회의록키`에 평문으로 저장합니다. 키 저장 체크를 끄고 적용하거나 ‘키 삭제’를 누르면 기존 키 파일을 삭제합니다. 자료를 다른 사람에게 전달할 때 이 키 파일을 제외하세요. 공개 소스의 기본 빌드 설치 파일에는 체험용 기본 키, 개인 키, 시험 회의 기록이 들어 있지 않습니다. 프로그램을 제거해도 자료와 키는 보존되므로 공용 PC에서는 제거 전에 ‘키 삭제’를 사용하세요.

프로젝트 설명은 요약 요청에 녹취와 함께 전달되며 음성 인식 단계에 별도 전달하지는 않습니다. 원음·전사와 설명은 AI 분석을 실행할 때 외부로 전송됩니다.

## 확인한 범위

프리셋 보존, 프로젝트별 기록 분리, 원음 보관, 잘못된 입력·인증 차단, 손상 설정 보존을 자동 테스트했습니다. 기존 브라우저 버전의 가상 마이크·모의 AI 흐름에 이어 설치형 화면 엔진에서 프리셋 표시와 가상 마이크 녹음을 확인했습니다. 실제 유료 AI 응답 품질·노트북 마이크 음량 적용·회의실 녹음 품질·장시간 녹음은 사용자 노트북에서 별도 확인해야 합니다. 여러 사람의 전체 회의를 정리하며 발언자를 자동 구분하지 않습니다.

설치 구조는 Microsoft의 [WebView2 배포 안내](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)와 Inno Setup의 [사용자별 설치 안내](https://jrsoftware.org/ishelp/topic_admininstallmode.htm)를 따릅니다.
