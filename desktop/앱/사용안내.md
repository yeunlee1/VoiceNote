# VoiceNote

**회의 시작 → 회의 종료** 순서로 사용합니다. 회의명·참석자·안건 메모를 적거나 출력 형식을 바꾸고 싶을 때만 먼저 `회의 준비`를 펼칩니다. 종료하면 음성을 이 PC에 먼저 저장하고, AI 전사와 요약을 진행한 뒤 지난 회의 목록에 회의록을 보관합니다.

별도 DB·Node 설치는 필요 없습니다. Windows 10(버전 2004 이상) 또는 11의 x64 환경에서 독립 프로그램 창으로 실행됩니다. 자동 분석에는 인터넷과 사용 가능한 OpenAI API 키가 필요합니다. ChatGPT 구독과 API 사용료는 별개입니다.

## 처음 실행

1. `VoiceNote-1.3.0-설치.exe`를 실행해 설치하고 바탕화면의 `VoiceNote` 아이콘을 엽니다. 설치 파일명 앞에 배포 날짜가 붙을 수 있습니다. 이전 버전 위에 설치하면 같은 위치를 갱신하고 회의 자료는 그대로 둡니다. WebView2가 없으면 설치 중 인터넷으로 준비합니다.
2. 화면 오른쪽 위 `설정`을 누르고 `AI 연결`에서 API 키를 입력한 뒤 `키 등록·변경`을 누릅니다. 개인 노트북에서는 `이 PC에 키 저장`으로 다음 실행에도 사용할 수 있습니다. 같은 곳에서 키 삭제와 요약 모델 선택도 합니다. 입력한 키는 화면에 다시 표시하지 않습니다. 공개 소스의 기본 빌드에는 체험용 기본 키가 없으므로, 분석하려면 자신의 OpenAI API 키를 먼저 등록해야 합니다.
3. 필요하면 `회의 준비`를 눌러 회의명, 날짜, 출력 형식, 참석자, 상세 회의내용을 적습니다. 펼치지 않아도 오늘 날짜와 기본 출력 형식으로 시작할 수 있습니다. 회의명은 비워 두어도 됩니다. 비워 두면 분석할 때 AI가 회의 내용을 보고 정합니다.
4. 녹음 전에 참석자에게 녹음과 AI 분석(OpenAI 전송)을 알려 주세요. 시작 버튼 아래에 같은 안내가 늘 보입니다.

1.2.0까지 쓰던 프로젝트는 1.3.0에서 없어졌습니다. 프로젝트에 쌓인 회의 기록은 지우지 않고 지난 회의 목록에 함께 보여 주며, 그 기록에는 `이전 프로젝트: 이름` 꼬리표가 붙습니다. 옛 기록도 열어 보고 다시 분석할 수 있습니다. 새 회의는 프로젝트 없이 한 목록에 쌓입니다.

## 회의 진행

- **회의 시작**은 분석할 수 있는 API 키(또는 체험 횟수)가 있고 회의 날짜가 올바르면 바로 눌러집니다. 상세 회의내용이 4,000자를 넘거나, 내 형식을 골랐는데 저장된 내 형식이 없으면 버튼 아래에 고칠 항목이 표시됩니다.
- **상세 회의내용**은 이번 회의의 안건·배경 메모입니다. 회의 기록에 함께 저장되고 다시 열 때 복원되며, 요약 요청에는 사전 참고 자료로만 전달됩니다. 회의록 내보내기 파일에는 넣지 않습니다.
- 앱 화면이 마이크를 쓰려고 하면 따로 묻지 않고 허용합니다. Windows 설정의 개인 정보 보호 › 마이크에서 앱의 마이크 사용을 꺼 두었다면 그 설정이 우선합니다. 처음에는 20~30초 시험 녹음을 하고 재생해 실제 자리의 목소리가 들리는지 확인하세요.
- 녹음 중에는 시작 버튼 자리에 **회의 종료**가 나타납니다. 녹음·분석·저장 중에는 회의 정보와 설정을 바꿀 수 없습니다. 회의 종료를 누르면 녹음을 마무리하고 모든 원음 파일을 저장한 뒤 전사·요약을 자동 실행합니다. ‘회의록 저장 완료’가 표시되면 지난 회의 목록에 남습니다.

`마이크 음량 100% 설정`은 Windows 기본 입력 마이크의 음량을 100%로 설정하고 음소거를 해제합니다. 설정은 도구를 종료해도 유지되며 스피커 음량과 마이크 부스트는 바꾸지 않습니다. 소리가 찢어지면 Windows 입력 음량을 낮추세요.

긴 회의는 파일당 약 59분 또는 22MB에 가까워질 때 다음 파일로 이어집니다. 종료할 때 모든 파일을 순서대로 저장하고 분석합니다. 녹음 중에는 아직 디스크에 저장되지 않았으므로 창 닫기·절전을 피하세요. 마이크가 분리되면 녹음이 중단될 수 있습니다.

## 설정

오른쪽 위 `설정`을 누르면 다섯 구역으로 나뉜 창이 열립니다. 녹음·분석·저장 중에는 이 창의 입력이 잠깁니다.

- **AI 연결**에서는 API 키를 등록·삭제하고, `이 PC에 키 저장` 여부와 요약 모델을 고릅니다.
- **출력 형식**에서는 새 회의가 시작할 `기본 출력 형식`을 고르고 `내 형식`을 만듭니다. 내 형식은 하나만 만들 수 있고, 넣을 항목·순서·항목 이름과 AI에게 줄 추가 지시를 정해 저장하거나 삭제합니다. `예시 미리보기`를 펼치면 편집 중인 형식의 모양을 바로 볼 수 있습니다. 기본 출력 형식을 내 형식으로 정했는데 저장된 내 형식이 없으면 새 회의는 회의록 형식으로 시작합니다.
- **저장 위치**에서는 오디오·전사문·요약본 사본을 쓸 폴더를 각각 고릅니다. 각 줄의 `폴더 고르기`를 누르면 Windows 폴더 선택 창이 열리고, `사용 안 함`을 누르면 그 종류의 사본을 쓰지 않습니다. 고른 폴더는 실제로 파일을 쓸 수 있는지 확인한 뒤에 저장합니다.
- **설정 파일**에서는 설정을 파일로 내보내거나 불러옵니다.
- **회의자료 폴더**에서는 앱이 보관한 회의 기록과 원음이 든 폴더를 엽니다.

### 고른 폴더에 사본 저장

저장 위치를 고르면 분석이 끝날 때마다 앱 안 기록은 그대로 두고 고른 폴더에 사본을 씁니다. 전사문은 `.txt`, 요약본은 `.md`와 `.txt` 두 파일, 오디오는 녹음한 원음 파일입니다. 파일 이름은 `날짜-차수-회의명-결과번호` 순서로 만들고(예: `2026-10-22-01차-주간 점검-1a2b3c4d-요약.md`), 같은 이름의 다른 파일이 이미 있으면 덮어쓰지 않고 이름 끝에 `(2)`, `(3)`을 붙입니다. 다시 분석해 제목이 바뀌어도 같은 원음은 한 번만 복사합니다.

사본을 쓰지 못해도 회의 결과는 앱 안에 저장됩니다. 이때 결과 창과 상태 줄에 실패한 종류와 이유가 나옵니다. 설정에서 폴더를 확인한 뒤 결과 창의 `고른 폴더에 다시 저장`을 누르면 아직 저장하지 못했거나 사라진 사본만 다시 씁니다. 폴더를 바꾼 뒤 누르면 새 폴더에 없는 사본을 쓰고, 옛 폴더의 사본은 지우지 않습니다. 저장 위치를 하나도 고르지 않았으면 이 버튼 대신 안내만 보입니다.

### 설정 파일

`설정 내보내기`는 요약 모델·기본 출력 형식·내 형식·저장 위치를 `<오늘 날짜>-VoiceNote-설정.json` 파일 하나로 내려받습니다. API 키, 체험 횟수, 회의·녹음·사용량은 넣지 않습니다.

`설정 불러오기`로 파일을 고르면 바뀔 값을 항목마다 먼저 보여 주고, `이 값으로 바꾸기`를 눌러야 실제로 바꿉니다. 이 PC에 없는 저장 위치나 이 앱의 목록에 없는 요약 모델은 그 줄만 적용하지 않고 이유를 함께 보여 줍니다. 파일에 저장 위치가 아예 없으면(Android에서 만든 파일 등) 지금 저장 위치를 그대로 두고, 저장 위치 가운데 빈 값은 `사용 안 함`으로 바꿉니다. 파일의 내 형식이 비어 있으면 지금 내 형식을 지웁니다. 여러 값을 바꾸다가 하나라도 저장하지 못하면 모두 이전 값으로 되돌립니다. 128KiB를 넘거나 UTF-8로 저장되지 않은 파일은 읽지 않습니다.

1.2.0까지의 프로젝트 설정 파일을 고르면 "이전 버전의 프로젝트 설정 파일입니다. 프로젝트 기능이 없어져 불러올 수 없습니다."라고 알리고 아무것도 바꾸지 않습니다.

## 보관 자료

자료는 `%LOCALAPPDATA%\MeetingJournal\회의자료`에 저장됩니다. 새 회의는 `회의기록` 폴더에 쌓입니다. 1.2.0까지 쓰던 `프로젝트-01`~`프로젝트-03` 폴더는 그대로 두고 읽기만 하며, 옛 회의를 다시 분석한 결과는 그 회의가 있던 폴더에 함께 저장합니다. 내 형식은 `회의자료\내형식.json`, 요약 모델·기본 출력 형식·저장 위치는 `MeetingJournal\AI설정.json`에 저장됩니다. 설치 폴더와 분리되어 프로그램 업데이트나 제거 후에도 회의 자료는 보존됩니다.

- `원음-…webm` 등의 파일은 녹음입니다. 브라우저에 따라 m4a 또는 wav가 될 수 있습니다.
- `녹음-…json`은 회의 정보와 원음 파일 목록입니다.
- `전사-…txt`는 요약 전에 저장한 전사 원문입니다. 요약에 실패해도 지난 회의에서 다시 불러와 사용할 수 있습니다.
- `회의-…json`은 분석 결과 하나입니다. 전사 원문·회의록·출력 형식·반영한 의견을 보관하며, 한 번 저장한 결과는 고치지 않습니다. 같은 이름의 `.md`와 화면의 TXT·Markdown·JSON 다운로드에는 회의록만 담고 전사와 사전 배경은 제외합니다.
- `평가-…json`은 그 결과에 남긴 별점과 의견입니다.
- `사본기록-…json`은 고른 폴더에 어떤 사본을 어디에 썼는지 적은 기록입니다.

다른 PC로 옮길 때는 프로그램을 설치한 뒤 **회의자료 폴더**를 같은 사용자 자료 위치에 복사합니다. 대상에 이미 기록이 있으면 덮어쓰지 말고 폴더를 먼저 보관하세요. API 키는 새 PC에서 다시 입력하고, 설정은 `설정 내보내기`로 옮길 수 있습니다. ‘현재 화면 비우기’는 보관 파일을 삭제하지 않습니다. 회의 자료는 여러 PC 사이에 자동으로 동기화되지 않습니다.

## 회의 결과 창

왼쪽 지난 회의를 누르면 회의 결과 창이 열립니다. 위쪽 `정리본`·`전사문` 탭으로 정리된 내용과 녹음에서 인식한 글을 보고, 보고 있는 탭의 내용을 `복사`하거나 `텍스트 파일로 저장`해 메신저·메일로 공유합니다. 모델별 AI 사용량과 Markdown·JSON 저장은 `AI 사용량 · 다른 형식으로 저장`을, 전사 수정과 다시 분석은 전사문 탭의 `전사 고치기 · 다시 분석`을 펼쳐 씁니다. 새 회의를 하려면 `회의 준비`를 누르세요.

### 요약 평가와 의견 반영

정리본 아래 `이 요약 평가`에서 별 1~5개와 의견(1,000자 이내)을 남기고 `평가 저장`을 누릅니다. 별점과 의견은 둘 중 하나만 있어도 저장되며 요금이 들지 않습니다. 같은 별을 다시 누르면 별점을 지웁니다.

의견을 적으면 `의견 반영해 다시 정리`가 켜집니다. 누르면 평가를 먼저 저장하고, 저장된 전사 전체와 지금 결과의 출력 형식으로 요약만 다시 요청합니다. 원음을 다시 전사하지는 않지만 요약 요금이 추가로 들고, 긴 회의는 여러 번 나눠 요청할 수 있습니다. AI는 앞선 정리본을 보지 않고 전사를 다시 읽으므로 ‘두 번째 항목’처럼 위치를 가리키기보다 무엇이 어떻게 틀렸는지 적어 주세요. 의견에 있더라도 전사에 없는 내용은 만들지 않도록 요청하고, 의견이 전사와 맞지 않으면 전사를 따르고 확인 필요로 남기게 합니다.

저장된 전사가 없으면 "저장된 전사가 없어 의견을 반영할 수 없습니다."라고 알리고 멈춥니다. API 키가 없으면 다시 정리 대신 설정 창을 열어 키 등록을 안내합니다. 요약이 실패해도 평가는 저장되어 있고 앞선 결과는 그대로입니다.

### 결과 버전

다시 분석하거나 의견을 반영해 다시 정리하면 새 결과로 따로 저장됩니다. 지난 회의 목록에는 녹음마다 가장 최근 결과 하나만 보이고, 평가한 결과에는 별 개수가 붙습니다. 같은 회의의 결과가 둘 이상이면 결과 창 위쪽 `결과 버전`에서 앞선 결과를 골라 그때의 본문·출력 형식·평가를 다시 볼 수 있습니다. 의견을 반영해 만든 결과에는 `의견 반영본` 표시가 붙습니다. 평가와 사본 저장은 지금 열어 둔 결과에 적용됩니다.

## 저장이나 분석이 실패했을 때

- 음성 저장이 실패하면 분석을 시작하지 않습니다. 창을 닫지 말고 디스크 공간과 폴더 쓰기 권한을 확인한 뒤 ‘저장·분석 다시 시도’를 누르세요.
- 음성 저장 후 분석이 실패하면 원음은 남습니다. 앱을 다시 실행해 ‘분석 대기’ 회의를 열고 API 키를 확인한 뒤 다시 분석할 수 있습니다.
- 일부 원음만 저장된 회의는 원래 녹음 창에서 나머지 저장을 완료해야 합니다. 이미 닫은 창의 미저장 음성은 복구할 수 없습니다.
- 회의록만 저장하지 못했다면 결과 창의 ‘저장 다시 시도’를 사용합니다. 이 동작은 AI를 다시 호출하지 않습니다.
- 고른 폴더에 사본을 쓰지 못했다면 설정에서 폴더를 확인한 뒤 결과 창의 ‘고른 폴더에 다시 저장’을 누르세요. 이 동작도 AI를 호출하지 않습니다.
- 실패한 AI 호출에도 비용이 발생했을 수 있습니다. 길이 한도에 걸리면 구간을 나눠 최대 6회 추가 요청합니다. 잔액·사용량·통신 오류에는 자동 재시도하지 않습니다. ‘다시 분석’과 ‘의견 반영해 다시 정리’에도 비용이 발생합니다.
- 인식된 사람 이름·품목 코드·수치·부정 표현과 담당자·기한을 확인하세요. 녹취에 없는 내용은 만들지 않도록 요청하지만 결과는 검토가 필요한 초안입니다.

1.0.1부터 전사 원문은 요약 전에 자동 보관합니다. 회의 결과 창의 전사문 탭에서 ‘전사 고치기 · 다시 분석’을 펼치면 ‘전사 원문 저장’으로 직접 내려받을 수도 있습니다. 이전 버전에서 실패한 회의의 텍스트를 복사했다면, 해당 지난 회의를 열어 전사 칸에 붙여넣고 ‘입력한 전사로 다시 분석’을 누르세요. 이 버튼은 입력한 글을 사용하므로 음성을 다시 전사하지 않습니다.

요약 모델은 `설정 › AI 연결`에서 GPT-6.1 Sol(기본), GPT-6 Luna, GPT-6 Astra 중에 고릅니다. 1.2.0에서 GPT-6 Sol과 GPT-5.6 Terra는 목록에서 빠졌고, 이 두 모델을 저장해 둔 경우 설정에서 모델을 한 번 다시 고르면 됩니다. medium 추론 강도와 요청당 출력 상한은 서버가 정합니다. 회의 결과 창의 ‘AI 사용량 · 이 회의 누적’에는 API가 알려준 입력·출력·합계 토큰을 실제 응답 모델별로 표시하고, 사용량을 받지 못한 요청은 0이 아니라 미제공으로 표시합니다. 같은 회의를 다시 분석하면 실패한 요청을 포함해 앞선 사용량에 이어서 더합니다. 다시 분석한 결과는 새 결과로 저장되며, 이전 결과와 그때의 사용량 기록은 `결과 버전`에서 다시 볼 수 있습니다. 새 회의를 준비하거나 녹음을 시작하면 사용량은 0부터 다시 셉니다. 핵심과 이유를 문장으로 설명하고 합의·제안·미확정 사항을 구분하도록 요청합니다. 긴 전사는 최대 24,000자씩 나눠 앞 구간의 회의록과 함께 처리합니다. 출력 상한은 입력 글자 수 제한이나 확정 과금량이 아닙니다. 길이 한도에 도달한 구간은 더 작게 나눠 최대 6회 추가 요청합니다. 분당 처리량 제한이나 계정 잔액·지출 한도는 자동 분할로 해결하지 않습니다. API 응답에 요청 ID가 있으면 오류에 함께 표시합니다.

## 출력 형식

`회의 준비`의 출력 형식에서 회의록·핵심 요약·업무 정리·내 형식 중 하나를 회의마다 고릅니다. 새 회의는 설정의 `기본 출력 형식`으로 시작하고, 고른 형식은 회의 기록에도 함께 남아 다시 열거나 다시 분석할 때 같은 형식을 씁니다. `예시 보기`를 누르면 고른 형식으로 정리한 예시가 나옵니다. 내 형식은 `설정 › 출력 형식`에서 만들고 고치며, 내 형식을 골랐는데 저장된 것이 없으면 회의 준비에 `내 형식 만들기` 버튼이 나옵니다. 이미 저장된 회의는 당시 내 형식 정의대로 보여 줍니다. 핵심 요약은 전체 흐름과 주제별 요지를, 업무 정리는 할 일·담당·기한과 미확정 항목을 중심으로 보여 줍니다. 어느 형식이든 전사에 없는 발언·담당·기한은 만들지 않도록 요청합니다. 출력 형식 정보가 없는 이전 기록은 회의록 형식으로 열립니다.

## 회의 제목과 날짜별 기록

AI가 회의 내용에 맞춰 제목을 정하고, 지난 회의 목록에는 날짜·그날의 차수·제목을 표시합니다. 차수는 날짜마다 1차부터 매깁니다. 옛 프로젝트 기록의 차수는 그때 값을 그대로 쓰므로 같은 날짜에 옛 기록과 새 회의가 둘 다 1차일 수 있고, 옛 기록에는 프로젝트 꼬리표가 붙어 구분됩니다. 같은 녹음의 재분석은 같은 차수를 유지하고 최신 결과를 목록에 표시합니다. 이전 결과 파일도 보존합니다.

전사는 분석 전에 저장합니다. 회의록에는 전사를 붙이지 않습니다. 회의록 형식은 상단에 전체 방향·주요 결정·다음 할 일·남은 쟁점을 요약하고 아래에 상세 설명을 표시합니다.

자동 분할 추가 요청 상한에 도달하면 전사를 유지하고 중단합니다. 성공 구간 재사용은 같은 화면에서 재시도할 때 적용되며, 프로그램을 닫으면 처리 중 캐시는 사라집니다. 저장된 전사는 재실행 후 다시 불러와 분석할 수 있습니다.

## 키와 참고 자료

키 저장을 선택하면 `%LOCALAPPDATA%\MeetingJournal\.env.회의록키`에 평문으로 저장합니다. 키 저장 체크를 끄고 적용하거나 ‘키 삭제’를 누르면 기존 키 파일을 삭제합니다. 자료를 다른 사람에게 전달할 때 이 키 파일을 제외하세요. 공개 소스의 기본 빌드 설치 파일에는 체험용 기본 키, 개인 키, 시험 회의 기록이 들어 있지 않습니다. 프로그램을 제거해도 자료와 키는 보존되므로 공용 PC에서는 제거 전에 ‘키 삭제’를 사용하세요.

상세 회의내용과 다시 정리할 때 적은 의견은 요약 요청에 전사와 함께 전달되며, 음성 인식 단계에는 전달하지 않습니다. 원음·전사·상세 회의내용·의견은 AI 분석을 실행할 때 외부로 전송됩니다.

## 확인한 범위

옛 프로젝트 기록을 합쳐 읽는 보관함 구조, 원음 보관, 고른 폴더 사본(덮어쓰기 방지와 실패 기록), 설정 파일 2판 검증, 평가와 의견 반영 흐름, 잘못된 입력·인증 차단을 자동 시험했습니다. 설치형 프로그램의 자체 검사는 설정 버튼·지난 회의 목록 표시와 가상 마이크 녹음을 확인합니다. 실제 유료 AI 응답 품질·노트북 마이크 음량 적용·회의실 녹음 품질·장시간 녹음은 사용자 노트북에서 별도 확인해야 합니다. 여러 사람의 전체 회의를 정리하며 발언자를 자동 구분하지 않습니다.

설치 구조는 Microsoft의 [WebView2 배포 안내](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)와 Inno Setup의 [사용자별 설치 안내](https://jrsoftware.org/ishelp/topic_admininstallmode.htm)를 따릅니다.
