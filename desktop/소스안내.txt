버전 1.3.0
VoiceNote Windows 설치형 소스 (이전 이름: 프로젝트 회의록, 1.0.3 소스 ZIP에서 이어짐)

프로그램.cs: 독립 Windows 창, WebView2, 서버 시작·종료 처리, 로컬 화면의 마이크 허용, 저장 위치 폴더 선택 창 (실행 파일 이름·AppId·자료 위치 %LOCALAPPDATA%\MeetingJournal는 기존과 같음. 검증용 --data-root <폴더>는 자료 폴더만 바꿔 실행)
앱/화면: HTML·CSS·JavaScript 화면 (회의 준비·녹음·분석·완료 단계, 설정 창, 회의 결과 창의 평가·의견 반영·결과 버전·사본 상태)
앱/서버.cjs: 최초 배포 ZIP에 들어 있던 번들 JavaScript를 수정한 서버. 번들 이전 원본 TypeScript 프로젝트는 제공받지 않았습니다.
앱/AI모델.cjs: 요약 모델 목록과 모델별 출력 상한, 응답 사용량 해석
앱/AI사용량.js: 모델별 AI 사용량 누적 도구 (서버가 /ai-usage.js로 화면에 제공)
앱/회의보관.cjs: 기본 보관함(회의기록)과 옛 보관함(프로젝트-01~03)의 녹음·원음·전사·회의 결과·평가·내 형식 보관. 옛 보관함은 읽기와 다시 분석 결과 저장만 함
앱/설정파일.cjs: 설정 파일 2판(voicenote-settings, 요약 모델·기본 출력 형식·내 형식·저장 위치)의 생성과 검증, 저장 위치 폴더 쓰기 확인. 1판 프로젝트 설정 파일은 정해진 안내와 함께 거절
앱/사본저장.cjs: 분석 결과의 전사문·요약본(.md·.txt)·원음 사본을 고른 폴더에 쓰고 사본 기록을 남김 (같은 이름 파일을 덮어쓰지 않음)
앱/회의문서.cjs: 회의 결과를 Markdown과 텍스트로 바꾸는 공용 변환기 (텍스트는 Android 앱과 같은 모양)
앱/체험권한.cjs: 설치 패키지 기본 키의 3회 체험·해제 상태 관리 (체험권한.json은 사용자 자료 폴더에 저장)
앱/출력형식.js: 출력 형식(회의록·핵심 요약·업무 정리·내 형식)의 이름·예시, 내 형식 검증·AI 지시·항목 구성 (서버가 /formats.js로 화면에 제공, 휴대폰 assets/formats.js와 같은 파일)
앱/마이크제어.cjs, 앱/마이크음량.ps1: Windows 기본 입력 마이크 음량 100% 설정
앱/설치형서버.cjs: 설치형 사용자 저장 경로, 설치 폴더의 기본키.json 연결, 부모 프로세스 종료 처리
설치/빌드.ps1, 설치/설치파일.iss: 실행 파일 컴파일 및 Inno Setup 설치 파일 제작
설치/VoiceNote-심볼.svg, 설치/VoiceNote.ico: 저장소 루트 브랜드VoiceNote.svg·VoiceNote.ico의 사본 (실행 파일·설치 파일·창 아이콘)
앱/*.test.cjs, tests/*.test.cjs: 자동 테스트 (tests/fixtures는 공통 시험 자료, tests/옛기록.cjs는 옛 프로젝트 기록을 만드는 시험 도구)

소스 묶음(ZIP)에는 API 키, 회의 기록, 실행 파일, Git 이력, 외부 빌드 의존성을 넣지 않습니다.
빌드에는 Windows .NET Framework 4.8, Inno Setup 6, Node v24.18.0 x64 실행 파일, Microsoft.Web.WebView2 1.0.4258.31 패키지 및 WebView2 설치 부트스트래퍼가 필요합니다.
빌드.ps1의 BuildRoot 기본값은 실행할 때마다 프로젝트 안의 산출물\데스크톱\<yyyy-MM-dd-HHmmss> 폴더입니다. NodePath·DependencyRoot 기본값은 현재 PC 경로이므로 다른 PC에서는 인수로 지정하세요. BuildRoot\배포가 이미 있으면 덮어쓰지 않고 멈춥니다.
빌드.ps1은 한글이 든 UTF-8(BOM 포함) 스크립트라 Windows PowerShell 5.1과 PowerShell 7 어느 쪽으로도 실행할 수 있습니다. 고쳐 저장할 때 BOM을 지우면 5.1에서 구문 오류로 멈춥니다.
빌드.ps1의 DefaultKeyFile은 기본값이 비어 있어 지정하지 않으면 기본 키 없이 만듭니다. 체험용 기본 키를 넣을 때만 -DefaultKeyFile로 apiKey JSON 파일을 명시하며, 키는 배포 폴더의 앱기본키.json에만 들어가고 값은 출력하지 않습니다. 소스와 소스 묶음, 구성.json 목록에는 기본키.json이 없습니다.
DependencyRoot 아래에 WebView2 패키지를 WebView2 폴더로 풀고 MicrosoftEdgeWebview2Setup.exe를 놓습니다.
실행 예: .\설치\빌드.ps1 -BuildRoot "D:\VoiceNote빌드" -NodePath "D:\도구\node.exe" -DependencyRoot "D:\VoiceNote빌드\의존성"
테스트 예: node --test 앱/*.test.cjs tests/*.test.cjs
공개 저장소라 push 전 비밀 검사 훅을 씁니다. 저장소를 받은 PC마다 한 번 .githooks\pre-push와 .githooks\push-비밀검사.cjs를 .git\hooks에 복사합니다. 훅은 보낼 원격에 아직 없는 커밋과 태그의 바뀐 파일 전체 내용(바이너리·UTF-16 포함), 파일 이름, 커밋·태그 메시지에서 이 PC에 저장된 실제 API 키 값(%LOCALAPPDATA%\MeetingJournal\.env.회의록키)과 키 모양 문자열을 찾고, 키·서명 파일과 속을 읽을 수 없는 압축·실행 파일을 이름으로 막습니다. 찾으면 push를 멈추고 값은 출력하지 않습니다. 훅 시험은 sh .githooks/push-비밀검사-시험.sh입니다.
