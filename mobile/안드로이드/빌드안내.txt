안드로이드 빌드 (VoiceNote 1.2.0, versionCode 4)

이 폴더는 Windows 앱과 같은 Sol 요청 양식을 쓰는 Android 네이티브 앱입니다. WebView는 APK 안의 화면만 표시하며 녹음, API 통신, 파일 보관·공유, 설정 파일 내보내기·불러오기(SAF 문서 선택 창)는 Java 코드가 처리합니다.

필요 도구

- Node.js 22 이상
- JDK 21
- Android SDK platform android-36, build-tools 36.0.0, platform-tools

빌드.ps1의 ToolRoot 아래에 SDK와 도구/JDK/<JDK폴더>를 준비합니다. 기본 ToolRoot는 C:\DEV\VoiceNote\2026-09-30-회의록도구-안드로이드 입니다. APK와 빌드 중간 파일은 OutputRoot에 저장하며, 기본값은 실행할 때마다 프로젝트 안의 산출물\안드로이드\<yyyy-MM-dd-HHmmss> 폴더입니다. SDK 라이선스에 동의해야 합니다.

PowerShell 실행

  .\안드로이드\빌드.ps1 -DebugBuild
  .\안드로이드\빌드.ps1 -DefaultKeyFile '<공용 기본 키 JSON 파일>'

요약 요청 양식은 desktop\앱\서버.cjs를 빌드 입력으로 직접 사용합니다(ServerScript 인수로 바꿀 수 있음). 스크립트는 서버를 잠시 로컬로 열고 모의 응답으로 회의록(meeting)·핵심 요약(summary)·업무 정리(tasks) 세 양식을 summary-<형식>.json으로 추출합니다. 외부 AI는 호출하지 않습니다. 세 양식이 같거나 사용자 메시지 필드가 휴대폰과 다르면 빌드를 멈춥니다.

공용 기본 키

DefaultKeyFile은 apiKey 속성이 있는 JSON 파일입니다. 기본값은 빈값이라 명시하지 않으면 키가 들어가지 않습니다. 명시하면 release 빌드의 패키징 임시 자산(stage-release\assets\default.key)에만 넣고, 서명 뒤 그 임시 파일과 서명 전 중간 APK를 지웁니다. 원본 assets, 소스 압축, 로그에는 키를 넣지 않으며 값도 출력하지 않습니다. 검증용(DebugBuild)에 DefaultKeyFile을 주면 빌드를 멈춥니다. 빌드 끝에 APK 항목 이름만 읽어 공용 키 포함 여부, 개인 키 파일 부재, 세 요약 양식 포함을 확인합니다.

공용 기본 키는 TrialAccess.java 규칙으로 분석 3회까지만 씁니다. 공개 소스에는 해제문자가 없어(UNLOCK_SHA256 빈 값) 횟수 제한을 풀 수 없습니다. 개인 키를 등록하면 체험 제한 없이 개인 키를 씁니다. 체험 기록 파일(files/trial-access.json)은 설정 내보내기에 들어가지 않고 allowBackup=false를 유지합니다. 앱 안에서만 동작하는 제한입니다.

설정 파일

설치본의 초기 프로젝트 설정(assets/preset.json)은 빈값입니다. 이전 버전에서 명시적으로 저장한 설정.json은 그대로 읽고, 출력 형식 값이 없으면 회의록으로 봅니다. 프로젝트는 처음 1개로 시작해 최대 3개까지 추가하고, 회의 기록이 없는 프로젝트만 삭제할 수 있습니다. 이전 버전의 4~9번 폴더는 지우지 않고 읽지도 않습니다. 프로젝트 창의 설정 파일에서 저장된 설정만 데스크톱과 같은 형식(voicenote-project-settings, version 1, 9칸 중 4~9번은 빈칸)으로 내보내고, 4~9번에 내용이 있는 파일은 불러오지 않습니다. 불러오기는 128KiB 이하 UTF-8 파일을 쓰기 전에 모두 검증하고, 미리보기에서 전체 교체를 확인해야만 저장하며, 저장 중 실패하면 이전 설정으로 되돌립니다. 회의 기록과 녹음은 건드리지 않습니다.

서명

개인서명 폴더의 회의록서명.p12와 서명암호.txt를 별도로 보관합니다. 이후 업데이트도 같은 서명으로 만들어야 기존 설치 위에 업데이트할 수 있습니다. 소스 압축이나 사용자 공유 파일에는 서명 파일과 API 키를 넣지 않습니다.

검증

- node --test tests/*.test.cjs : 시작 조건, 출력 형식 화면 구성, 체험 표시, 모델 목록, 데스크톱 설정 교환 모듈과의 판정·왕복 비교(JDK 필요)
- tests/SettingsExchangeTest.java, tests/TextChunksTest.java, tests/TrialAccessTest.java : 해당 소스와 함께 javac로 컴파일해 실행
- node tests/화면검증-브라우저.cjs <캡처폴더> : 헤드리스 Chrome 화면 검사
- AndroidChecks.java는 DebugBuild에만 포함됩니다. 검증 전용 가상기기에 설치한 뒤 실행합니다.

  adb shell am instrument -w kr.local.meetingjournal/kr.local.meetingjournal.AndroidChecks

가상기기는 도구 경로에 한글이 있으면 부팅 중 멈춥니다. C:\vn-emu\sdk(SDK 정션)와 C:\vn-emu\phone.avd(가상기기 정션)처럼 영어 경로로 연결해 실행합니다. 예: $env:ANDROID_SDK_ROOT='C:\vn-emu\sdk'; C:\vn-emu\sdk\emulator\emulator.exe -avd VoiceNotePhone -no-metrics

이 검증은 프로젝트 03에 시험 기록을 만들고, 프로젝트 설정과 저장된 키는 시험 뒤 되돌립니다. 실제 사용자 휴대폰 대신 검증 전용 가상기기에서 실행합니다. 실제 API 호출은 없습니다.
