# VoiceNote 1.7.0 구현 계획 — 지난 회의에서 내가 맡은 일 보기

> **실행하는 에이전트에게:** 작업마다 이 계획과 설계 문서를 함께 읽는다. 진행은 짝 작업 규칙(pair-working)과 superpowers:executing-plans(또는 superpowers:subagent-driven-development)를 따른다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 모든 회의의 남은 일을 모아 보여 주던 '아직 안 끝난 일' 목록을 없애고, 지난 회의를 누르면 그 회의에서 내가 맡은 일만 먼저 보여 주며, 다른 참석자에게는 사람별 글을 복사해 알리게 한다. Android 정리본에는 텍스트 파일 저장을 넣는다.

**구조:** 나를 정하고 내 일을 고르는 규칙은 `desktop/앱/할일정리.js` 한 곳에 둔다. Windows 화면·서버와 Android 화면(`assets/todos.js`, 같은 파일의 사본)이 그 함수를 쓰고, Android 네이티브(`Todos.java`)는 같은 입력으로 결과를 대조한다. 회의마다 고른 '나'는 회의에 붙는 작은 파일(Windows `나-<묶음 열쇠>.json`, Android `나.json`)에, 설정의 내 이름은 기존 설정 저장소에 둔다. 화면은 결과 탭을 `내 할 일 | 정리본 | 전사문`으로 늘리고, 지난 회의 목록에 `내 일 n`을 붙인다.

**기술:** Windows는 Node 서버(`desktop/앱/서버.cjs`, 묶인 파일을 직접 고친다), 보관 모듈(`회의보관.cjs`), WebView2 화면(`desktop/앱/화면`). Android는 Java(androidx 없음)와 WebView 화면(`mobile/안드로이드/assets`). 시험은 `node --test`, JVM 단독 Java 시험, 헤드리스 Chrome 화면 검사(`화면검증-브라우저.cjs`), 가상기기 `AndroidChecks`.

**설계:** `C:\DEV\VoiceNote\작업기록\2026-11-10-내할일보기\설계\2026-11-10-내할일보기-설계.md` (사용자 승인 2026-11-10 "응 이대로 진행하자"). 이 계획은 설계의 결정을 따른다. 둘이 어긋나면 설계가 우선이고, 어긋난 점을 짝과 사용자에게 알린다.

## 설계가 맡긴 것을 이 계획에서 정한 값

설계의 '만드는 사람에게 맡기는 것'과 설계가 말하지 않은 세부를 아래처럼 정했다. 사용자가 바꾸라고 하면 그 줄만 바꾼다.

| 무엇 | 정한 값 | 까닭 |
|---|---|---|
| 나를 판정하는 자리 | 화면이 `Todos.resolveMe`로 판정한다. 목록의 수는 Windows 서버·Android 네이티브가 같은 규칙으로 센다 | 화면은 저장된 선택과 설정 이름을 이미 갖고 있고, 목록은 회의를 열지 않고 세야 한다 |
| 체크·나 고르기 뒤 목록 갱신 | 지난 회의 목록을 다시 읽는다(1.6.0이 남은 일 목록을 다시 읽던 자리) | 수를 세는 곳을 하나로 둔다. 읽는 횟수는 1.6.0과 같다 |
| 나를 저장하는 동안의 보호 | 할 일 저장과 같은 대기 수(`todoPending`)를 함께 올린다. 결과 닫기, 다른 회의 열기, 업데이트 설치는 막히고, 새 회의와 현재 화면 비우기는 할 일 저장 때처럼 확인창을 거친다. 확인하고 넘어가면 늦게 온 응답은 원래 회의에만 저장되고 새 화면의 나와 안내를 바꾸지 않는다 | 할 일 저장의 지금 규칙과 똑같이 둔다. 안내도 기존 '저장하는 중' 문구다 |
| 닫은 뒤 돌아갈 목록 줄 찾기 | 목록의 줄마다 회의 묶음 열쇠(`groupId`)를 주고 화면이 보관함과 그 열쇠 둘로 찾는다 | 녹음 없이 만든 회의의 옛 결과를 보다 닫아도 같은 줄로 돌아간다. 서버도 보관함과 묶음 열쇠로 회의를 구분한다 |
| 나머지 일의 수 | 끝낸 일도 센다(시안과 같다). 복사 창의 담당 미정 안내는 남은 일만 센다 | 설계 문구 "담당자가 없는 남은 일" |
| Android에서 분석·의견 반영 직후 열리는 탭 | 정리본 | Android에는 `회의록 보기` 단추가 없고 분석이 끝나면 결과가 저절로 열린다. 그 열림이 `회의록 보기`에 해당한다 |
| Android 사람별 글을 만드는 자리 | 화면(`todos.js`)이 만들고 새 요청 `copyText`로 클립보드에 넣는다 | 글 모양을 한 파일에만 둔다. 요청 10만 자 제한에 걸리면 실패로 알린다 |
| 설정의 내 이름 저장 조작 | `내 이름 저장` 단추와 Enter | 글자를 적는 칸이라 바꾸는 즉시 저장하지 않는다 |
| Android 내 할 일 탭의 'AI 사용량 · 음성 포함 내보내기 · 다시 분석' 묶음 | 내 할 일 탭에서는 감춘다 | Windows는 그 묶음이 정리본 탭 안에만 있다 |
| 저장되지 않은 결과(`resultStored`가 거짓) | 체크와 나 고르기를 누를 수 없게 둔다 | 정리본의 체크 조건과 같다 |

함께 고치는 기존 결함이 하나 있다. Windows에서 `openMeeting`이 `result-status`에 적은 '수정본을 읽지 못해 AI 결과를 보여 줍니다' 안내를 바로 뒤의 `openDialog`→`showResultTab`이 지운다(`app.js:2092, 2109, 1682`). 설계가 "같은 안내를 낸다"고 했으므로 Task 5에서 안내를 창을 연 뒤에 적도록 고친다.

## 실행 방식과 검증

## 집중 검토 대상

설계가 직접 말하지 않았지만 실제 사용에서 먼저 문제가 될 입력이다. 각 줄의 시험은 담당 작업에 넣었다.

1. **공백이 섞인 이름.** 참석자·담당자·설정의 내 이름·저장된 선택에 이어진 공백, 전각 공백(U+3000), NBSP(U+00A0)가 들어 있다. 공백만 다르면 같은 사람으로 보고 Windows와 Android가 같은 답을 내야 한다(Task 1, Task 2).
2. **깨지거나 낡은 나 파일.** 내용이 깨졌거나, `version`이 다르거나, 이름이 지금 후보에 없다. 회의는 목록에 남고, 설정의 내 이름으로 다시 판정하며, 파일은 지우지 않아야 한다(Task 4, Task 10).
3. **아주 긴 글자.** 이름 200자, 할 일 문장 2,000자, 제목 160자와 파일 이름에 못 쓰는 글자. 화면은 줄을 바꾸고 가로로 넘치지 않으며, Android에서 10만 자를 넘는 사람별 글은 실패로 알리고 `복사함`으로 바꾸지 않고, txt 파일 이름은 70자 안에서 유효해야 한다(Task 7, Task 10, Task 11, Task 12).
4. **빠른 연속 조작과 저장 실패.** 체크를 연달아 누르거나, 나를 저장하는 중에 다른 회의를 누르거나 결과를 닫는다. 마지막으로 누른 값이 남고, 실패하면 저장이 확인된 상태로 돌아가며, 목록의 수가 화면과 어긋나지 않아야 한다(Task 3, Task 5, Task 9, Task 11).

- [ ] **Step 6: 마무리.** tm 34번과 하위 작업을 갱신하고, 사용자에게 요청 원문별 상태, 확인한 것과 못 한 것, push와 병합 허락 요청(저장소·브랜치·커밋 목록)을 보고한다. push는 허락 뒤에만 한다.
