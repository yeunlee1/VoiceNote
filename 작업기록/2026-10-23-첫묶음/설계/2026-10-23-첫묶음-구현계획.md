2. **검토**: 검토하는 쪽은 자기 작업 폴더를 건드리지 않는다. 그 커밋을 `산출물\2026-10-23-첫묶음-검토\<작업번호>\`에 `git clone --no-hardlinks` 뒤 `git checkout <끝 커밋>`으로 받아, 그 작업의 시험을 직접 다시 돌리고 변경을 설계·계획과 대조해 읽는다. 화면 작업이면 캡처를 직접 연다.
3. **피드백**: `%LOCALAPPDATA%\짝작업\VoiceNote\2026-10-23-첫묶음구현\검토-Task<번호>.md`에 '반드시 고칠 것'(확정된 결함, 설계·계획 미충족, 화면 품질, 회귀, 시험 실패)과 '선택'을 나눠 근거(경로:줄, 재현 명령)와 함께 남기고 메시지로 알린다.

6. 묶음 끝(Task 16)에는 전체 변경을 서로 한 번 더 보고, 새 검토자 한 명(서브에이전트)이 전체 브랜치를 본다. 일꾼은 짝 포함 동시에 3개까지다.

## 집중 검토 대상

설계가 직접 말하지 않았지만 실제 사용에서 가장 먼저 문제가 될 입력이다. 각 줄의 시험은 담당 작업에 넣었다.

1. 옛 보관함 폴더에 깨진 JSON, 남은 `.tmp`, 사람이 넣은 다른 파일이 섞여 있다. 목록과 열기는 정상이고 `skipped`만 늘어야 한다(Task 3, Task 10).
2. 회의 제목·참석자에 `<>:"/\|?*`, 이모지, 줄바꿈, 300자 제목이 들어 있다. 사본 파일 이름은 유효하고 제목 부분은 80자 이하이며 내용은 그대로여야 한다(Task 5, Task 12).
3. 저장 위치 폴더가 읽기 전용이거나 권한이 없거나 쓰는 도중 실패한다. 회의 저장은 성공하고, 실패한 종류와 이유를 정확히 알리고, 반쪽 파일을 남기지 않아야 한다(Task 5, Task 12).
4. 같은 날 같은 제목 회의 여러 개의 사본을 같은 폴더에 쓴다. 기존 파일을 덮어쓰지 않고 `(2)`, `(3)`이 붙어야 한다(Task 5, Task 12).
5. 의견에 줄바꿈·따옴표·지시문처럼 보이는 문장이 있거나 정확히 1,000자다. 요청 JSON이 깨지지 않고 1,000자는 받고 1,001자는 거절해야 한다(Task 1, Task 11).
