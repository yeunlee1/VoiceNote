**Files:**
- Create: `desktop/앱/진행기록.js`, `desktop/tests/fixtures/진행기록-예시.json`, `desktop/앱/진행기록.test.cjs`

**Interfaces:**
- Produces(전역 이름 `MeetingActivity`, Node는 module.exports. 할일정리.js와 같은 UMD 틀)
  - `MAX_ENTRIES = 30`, `LIMIT_SECONDS = 300`, `HINT`(「OpenAI는 일을 다 마친 뒤 한꺼번에 답을 보내서, 기다리는 동안에는 시간만 올라갑니다.」), `FAILURE_TYPES`
  - `lineText(event) -> string`, `requestLabel(event) -> string`
  - `create(kind, at) -> log` · log는 `{ id, kind, entries: [], open: null, seq: 0, startedAt: at }`. id는 crypto.randomUUID가 있으면 그것, 없으면 시각+난수
  - `add(log, event, at) -> entry` · entry는 `{ seq, at, type, text }`. 30줄 넘으면 앞에서 버림, seq는 이어짐
  - `openRequest(log, sendEvent, at, { size = null } = {}) -> open` · 보냄 줄을 add하고 `open = { label, since: at, phase: size == null ? 'wait' : 'upload', sent: 0, size, waitSince: size == null ? at : null }`
  - `progress(log, sent)`, `uploaded(log, at)`(phase 'wait', waitSince=at), `closeRequest(log)`
  - `lastIsFailure(log) -> boolean`(마지막 줄 type이 FAILURE_TYPES에 듦, 빈 일지는 거짓)
  - `lastEventAt(log) -> number|null`(마지막 실제 줄의 at)
  - `waitingText(open, now, limitOwner) -> string` · limitOwner는 'server'(Windows) 또는 'app'(휴대폰)
  - `clock(at) -> 'HH:MM:SS'`(그 기기 시각), `elapsed(seconds) -> 'm:ss'`, `mb(bytes) -> '4.1'`(1,048,576 기준 소수 한 자리, 0보다 크면 최소 0.1), `count(n) -> '2,310'`
  - `render(container, log, now, { limitOwner, maxRows = Infinity, document } = {})`, `tick(container, log, now, { limitOwner } = {})`
  - 두 앱은 render에 늘 자기 `document`를 넘김(모듈을 Node require로 넣은 시험 VM에서도 VM의 가짜 document로 그리게 하기 위함)

- type 표(필드 → 문구, 설계서 「일지 줄」과 같음)

| type | 필드 | 문구 |

- FAILURE_TYPES = timeout, uploadStall, requestStall, disconnected, apiError, badFormat, saveFailed, failed, canceled
- requestLabel: sendTranscript → `전사 · 조각 {part}/{total}`, sendSummary → `회의록 정리 · 구간 {part}/{total}`, sendCompact → `회의록 줄이기`, sendRefine → `의견 반영 · 구간 {part}/{total}`
- part는 숫자 또는 「2-1」 같은 글자(자동 분할 하위 구간)
- waitingText
  - phase 'upload': `음성 올리는 중 · {mb(sent)}/{mb(size)}MB`
  - phase 'wait'이고 지난 초 s(= (now - (waitSince ?? since)) / 1000 내림) ≤ 300: `응답 기다리는 중 · {elapsed(s)} / 최대 5:00`
  - 300 초과이고 'server': `응답 기다리는 중 · {elapsed(s)} · 제한 시간이 지나면 서버가 실패로 알려 줌`
  - 300 초과이고 'app': `응답 기다리는 중 · {elapsed(s)}`(실제 감시 결과가 일지에 오기 전에는 멈춘다고 단정하지 않음)
- render
  - log가 없거나 줄도 열린 요청도 없으면 비우고 container.hidden=true
  - 있으면 머리 `div.activity-head`(「AI 요청 기록」과, 실제 줄이 있으면 `span.activity-last` 「마지막 기록 {clock(lastEventAt)}」), `ol.activity-list`(aria-label 「AI 요청 기록」), 열린 요청이 있으면 `p.activity-hint`(HINT). container.hidden=false
  - 목록 줄은 `li > span.activity-time + span.activity-text`. 열린 요청은 마지막 `li.activity-wait`(시각 칸 「지금」, 글 waitingText)
  - maxRows는 기다림 줄을 포함한 전체 줄 수(열린 요청이 있으면 실제 줄 maxRows-1개 + 기다림 줄)
  - 같은 그림이면 DOM을 건드리지 않음: `log.id`·마지막 seq·열린 요청 label·phase로 만든 판 키를 `container.activityKey`에 두고 같으면 바로 돌아감
  - 일지 번호가 바뀌면 앞 줄을 남기지 않고 새로 그림
  - 기다림 글 노드를 `container.activityWait`에 둠(querySelector를 쓰지 않음)
- tick: `container.activityWait`가 있으면 textContent만 waitingText로 바꿈. 다른 노드는 건드리지 않음
