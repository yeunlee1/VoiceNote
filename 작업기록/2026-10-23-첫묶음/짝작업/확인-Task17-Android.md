## 결함

### D1 다시 저장할 것이 없으면 화면이 빈칸이 된다 — 반드시 고칠 것

- **재현.** 사본이 모두 저장된 결과를 열고 '고른 폴더에 다시 저장'을 누른다. 열었을 때 보이던 네 줄의 저장 목록이 사라지고, 사본 영역에는 버튼만 남는다. 상태 줄이나 알림에도 아무 말이 없다(`캡처\19-두번째저장후.png`).
- **근거.** `mobile/안드로이드/assets/app.js:261-263`의 `renderCopies`가 목록을 비운 뒤 `written`과 `failed`만 다시 그리고 `skipped`는 무시한다. 응답에는 skipped 4건이 들어 있다. Windows 화면(`C:\DEV\VoiceNote\desktop\앱\화면\app.js:1839`, 브랜치 `work/2026-10-23-프로젝트제거-설정화면`)은 같은 경우 "고른 폴더에 새로 저장할 사본이 없습니다."를 보여 준다.
- **판단.** 누른 결과를 알 수 없고 직전에 보이던 저장 목록까지 사라지는 상태 표시 결함이며, 두 앱의 표시가 다르다. 짝 작업 기준의 '화면 품질 결함(상태 표시)'에 해당한다. written·failed가 모두 비면 Windows와 같은 문장을 보여 주는 정도의 작은 수정으로 닫힐 것으로 본다.

### D2 고른 폴더가 사라지면 이유와 다시 고르라는 안내가 없다 — 반드시 고칠 것

- **재현.** 사본 폴더를 고른 뒤 그 폴더를 옮기거나 지우고 '고른 폴더에 다시 저장'을 누른다. 화면에는 "원음 · 파일을 쓰지 못했습니다."만 나온다.
- **원인.** 실제 ExternalStorageProvider는 없는 폴더의 하위 목록을 조회하면 `FileNotFoundException`을 안에서 잡고 null 커서를 돌려준다(logcat `W/DocumentsProvider … Missing file for primary:Documents/VoiceNoteAudio`). 그러면 `Copies.java:80`이 `IOException("고른 폴더를 읽지 못했습니다.")`을 던지고, `Copies.java:94-98`의 `error()`가 이 IOException을 일반 문구 "파일을 쓰지 못했습니다."로 바꾼다. 또 결과 화면의 실패 줄(`app.js:263`)은 "<종류> · <이유>"만 보여 줄 뿐, 설계의 "설정에서 폴더를 확인한 뒤 '고른 폴더에 다시 저장'을 누르세요." 같은 다음 행동 안내를 붙이지 않는다.
- **설계와 대조.** 설계 문서의 '폴더 고르기 › Android'는 "받은 권한이 나중에 끊기면(폴더 삭제, 권한 회수 등) 다음 사본 저장 때 실패로 알리고 다시 고르라고 안내한다"고 정한다. 실패를 알리는 부분은 충족하지만 다시 고르라는 안내가 없다.
- **판단.** 수용 조건 미충족이다. 최소한 null 커서를 "고른 폴더를 찾을 수 없습니다. 설정에서 폴더를 다시 골라 주세요." 계열의 이유로 바꿔야 한다. 결과 화면 실패 줄의 문장 형식을 Windows처럼 바꿀지는 Task 13 검토 판단에 맡긴다. AndroidChecks의 '새 폴더와 지워진 문서' 시험은 파일 기반 대체물과 합성 권한으로 돌기 때문에 이 null 커서 경로를 잡지 못했다.

### D3 폴더가 잠시 사라졌다 돌아오면 같은 원음을 또 쓴다 — 확정 결함, 우선순위 낮음

- **재현.** 원음 사본을 저장한 뒤 오디오 폴더를 잠시 옮긴다. 다시 저장을 한 번 눌러 실패시키고, 폴더를 원래 이름으로 되돌린 뒤 다시 저장한다. 그러면 같은 원음이 `…-원음-01 (2).m4a`로 한 벌 더 생긴다.
- **원인.** `Copies.java:117`(`attempt`)는 결과를 기록할 때 같은 종류·같은 폴더의 기존 항목을 모두 빼고 새 항목 하나만 넣는다. 그래서 실패 항목(`ok:false`)이 앞선 성공 항목과 그 문서 주소를 지운다(`덤프\23-폴더사라짐후-원음기록.json`). 폴더가 돌아와도 앱은 이미 쓴 문서를 모르고, 같은 이름이 있으니 `(2)`로 새로 쓴다.
- **설계와 대조.** 설계는 "원음은 녹음 id와 순번으로 이미 쓴 것을 판별한다. … 같은 원음을 또 복사하지 않는다"고 하고, 실패 표에서도 "원음은 같은 녹음이면 건너뜀"이라고 한다. 또 "아직 성공하지 않았거나 저장한 파일이 사라진 것만 쓴다"고 한다. 같은 코드 경로를 타므로 전사문·요약본도 같은 상황이면 `(2)`가 생길 것으로 보이지만, 기기에서 재현한 것은 원음뿐이다.
- **판단.** 확정 결함이라 짝 작업 규칙상 고칠 대상이다. 다만 원본 손실은 없고, 폴더가 잠시 접근할 수 없다가 복구된 경우에만 사본이 한 벌 더 생기므로 D1·D2보다 뒤로 둔다. 실패 때 이전 성공 항목의 주소를 남겨 다음 저장에서 `exists()`로 다시 확인하는 방식이 가장 작은 수정으로 보인다. Windows 사본 기록이 같은 방식인지는 확인하지 않았다.
