# 휴대폰 녹음 파일 불러오기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** VoiceNote Android 앱의 새 회의 화면에서 m4a 녹음 파일을 골라, 앱이 직접 녹음한 회의처럼 전사·정리하게 한다. 20분이나 22MB를 넘으면 다시 압축하지 않고 잘라 담는다.

**Architecture:** 새 클래스 `AudioImport`가 파일 판정·담기·자르기를 맡는다. 화면(`MainActivity`)은 문서 선택 창을 열고 빠른 판정만 한 뒤, 녹음 서비스(`MeetingService`)의 새 동작 `import`에 넘긴다. 서비스가 앱 안 임시 폴더에 담고, 다 담은 뒤에만 `Store.createImported`로 회의를 만들어 지금의 `analyze()`로 이어 간다.

**Tech Stack:** Android Java(API 26+, target 35), `MediaExtractor`·`MediaMuxer`·`ContentResolver`(SAF), WebView 화면(`assets/index.html`·`app.js`·`flow.js`), Node 시험(JVM 단독·헤드리스 Chrome 화면 검사), 이고라이트 캡처.

**Spec:** `작업기록/2026-11-13-통화녹음불러오기/설계/2026-11-13-휴대폰-녹음파일-불러오기-설계.md` (2026-11-13 사용자 승인 "진행해")

## Global Constraints

- 그대로 복사하는 한계: 길이 20분(1,200,000,000µs) 이하이고 크기 23,068,672바이트(22MiB, `MeetingService`의 `22*1024*1024`) 이하. 둘 다 안이면 원본 바이트를 그대로 `원음-001.m4a`로 담는다.
- 자르는 기준: 조각 길이 20분, 조각 크기 약 20MiB(20,971,520바이트) 중 먼저 닿는 쪽. 조각마다 시간은 0부터 다시 센다. 소리를 다시 압축하지 않는다.
- 자를 수 있는 형식은 오디오 트랙 MIME `audio/mp4a-latm`(AAC)뿐이다.
- 받지 않는 것: 앞 12바이트 offset 4가 `ftyp`가 아닌 파일, 오디오 트랙이 없는 파일, 4시간(14,400,000,000µs) 넘는 파일, 남은 공간이 파일 크기+50MiB(52,428,800바이트)보다 적은 경우.
- 안내 문구(정확히 이대로):
  - `‘<이름>’ 파일은 불러올 수 없습니다. m4a 녹음 파일만 불러올 수 있습니다.`
  - `‘<이름>’ 파일은 20분(22MB)이 넘는데 나눌 수 없는 형식입니다. 20분 이하 파일만 불러올 수 있습니다.`
  - `‘<이름>’ 파일은 4시간이 넘어 불러올 수 없습니다.`
  - `휴대폰 저장 공간이 부족해 파일을 불러오지 못했습니다.`
  - `파일을 읽지 못했습니다. 다시 골라 주세요.`
  - 이름을 알 수 없으면 `<이름>` 자리에 `고른 파일`을 쓴다.
- 파일은 SAF 문서 선택 창으로만 읽는다. 새 권한·`takePersistableUriPermission`을 쓰지 않는다. 원본을 쓰거나 지우지 않는다. 원본 파일 이름을 회의 기록에 저장하지 않는다.
- 회의는 조각을 다 담은 뒤에만 만든다. 담다가 실패하면 임시 폴더만 지우고 회의를 만들지 않는다. 임시 폴더는 앱 파일 영역의 `불러오기-임시\<임시 id>\`다.
- 막힘 조건은 '회의 시작'과 같다(`Flow.canStart`, `store.requireAccess`, `Store.notes`, `MeetingService.active`, `Updates.installing`, `fileIdle`).
- 시험 자료는 합성 음성과 합성 이름(김민수·박서연·이도현·최유진)만 쓴다. 실제 통화 녹음·`%LOCALAPPDATA%\MeetingJournal`을 쓰지 않는다. 브라우저 확인은 이고라이트(AgentTest 프로필)로 하고 Playwright는 쓰지 않는다.
- 가상기기와 실제 OpenAI 호출은 사용자 허락을 받은 뒤에만 한다. push·버전 올리기·릴리즈는 이 계획 밖이다.
- 새 소스 파일 첫 줄에 한국어 역할 한 줄을 둔다. 설명 주석은 설명할 코드 바로 아래에 둔다.

## Review Focus

1. **끝에 `moov`가 있거나 문서 제공자가 이어 읽기만 되는 파일**(클라우드 문서 등): `MediaExtractor`가 열지 못하면 앱이 멈추지 않고 '파일을 읽지 못했습니다' 안내를 낸다 → Task 2의 기기 시험 `importUnreadableCheck`(읽기 실패를 흉내 낸 주소).
2. **영상이 든 mp4, 오디오 트랙이 여럿인 파일**: 첫 오디오 트랙만 쓴다. 한계 안이면 원본을 그대로 담는다 → Task 2 `importVideoTrackCheck`(영상+음성 합성 mp4가 그대로 복사되고, 넘으면 오디오 트랙만 잘림).
3. **파일 선택 창이 열린 동안 다시 누르거나 다른 시작**: 두 번째 요청은 `fileIdle`로 거절되고 화면은 그동안 잠긴다 → Task 4 화면 검사 '선택 창이 열린 동안 시작·불러오기 단추가 잠긴다'.
4. **담는 중 앱이 끝남**: 남은 임시 폴더가 다음 실행에서 지워지고 회의 목록에 원음 없는 회의가 생기지 않는다 → Task 3 `importTempCleanupCheck`.
5. **이름을 주지 않는 문서 제공자**: 안내에 `고른 파일`이 쓰인다 → Task 1 JVM 시험 `label` 경계.
