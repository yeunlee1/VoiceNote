# 켤 때 새 버전이 있으면 업데이트할지 묻기 — 설계 (tm 39)

- 날짜 — 2026-11-17
- 작업 브랜치 — `work/2026-11-17-켤때업데이트묻기`(tm 37 브랜치 `096ba1a` 위)
- 함께 나가는 버전 — 1.7.0

## 사용자 요청과 결정

- 「앱이나, 윈도우에서 프로그램 켜지면 자동으로 업데이트가 있는지 감지해서 새로운버전이 있습니다. 업데이트하시겠습니까? 이렇게 물어볼수있는거 있으면 좋을거같아」
- 다시 묻기 — 「켤 때마다 다시 묻기 (Recommended)」(창 미리보기 확인함)
- 배포 — 「1.7.0에 넣고 배포 (Recommended)」

## 지금 동작

- 두 앱 모두 켤 때 새 버전을 확인함(1.5.0부터)
- 새 버전이 있으면 화면 위쪽 작은 `새 버전 X.Y.Z` 표시만 뜨고, 눌러서 `프로그램 정보`의 `지금 업데이트`로 설치함

## 바꿀 동작

- 켜서 확인한 상태가 처음 `available`(앱에서 받아 설치할 수 있음)이 되면 묻는 창을 띄움
  - 제목 「새 버전이 있습니다」
  - 내용 — `새 버전 X.Y.Z`, `지금 버전 A.B.C`, 「업데이트하시겠습니까?」
  - 안내 한 줄 — 프로그램 정보에 이미 있는 문장을 그대로 씀(Windows 「업데이트하면 VoiceNote가 잠시 닫혔다가 다시 열립니다. …」, 휴대폰 「설치하면 VoiceNote가 닫히고 새 버전으로 바뀝니다. …」)
  - 단추 — [업데이트] [나중에], [바뀐 점 보기](Windows는 창 안에서만, 개발용 브라우저에서는 숨김)
- [업데이트] — 지금 `지금 업데이트`와 같은 동작(Windows `startUpdate`, 휴대폰 `runUpdate('download')`)
  - 저장 안 한 내용 등 설치를 막는 이유가 있으면 받아 두기만 하고, 이유가 보이도록 `프로그램 정보`를 엶
- [나중에]·닫기 — 아무것도 받지 않음, 이번 실행에서는 다시 묻지 않음, 다음에 켜면 다시 물음
- [바뀐 점 보기] — 기존 `깃허브에서 보기`와 같은 페이지를 엶(새 버전의 바뀐 점은 앱 안 목록에 아직 없음)
- 묻지 않는 때
  - `manual`(앱에서 바로 설치할 수 없음)·`latest`·`unknown`·확인 기능이 없는 실행
  - 녹음·분석·저장 중이거나 다른 창이 열려 있으면 미뤘다가 끝난 뒤 그 실행에서 한 번 물음
- 화면 위쪽 작은 새 버전 표시는 그대로 둠

## 하지 않는 것

- 설치를 사람의 클릭 없이 시작하기(1.5.0의 원칙 「사람이 누를 때만 설치」를 지킴)
- 버전마다 한 번만 묻기, 건너뛸 버전 기억하기(사용자가 켤 때마다 다시 묻기를 고름)
- 새 버전의 바뀐 점을 앱 안에 받아 보여 주기

## 알려진 한계

- 묻는 창은 1.7.0 안에 들어가므로 1.7.0을 설치한 뒤 다음 버전부터 뜸, 1.6.0 사용자는 1.7.0을 지금처럼 작은 표시로 알게 됨
- 휴대폰은 앱 화면이 다시 만들어지면(앱을 완전히 닫았다 켜는 것과 같게) 다시 물을 수 있음

## 시험

- Windows `프로그램정보화면.test.cjs` — 처음 available에 창 1번, 나중에 뒤 같은 실행에서 다시 안 뜸, manual·latest에 창 없음, 녹음 중 미룸·끝난 뒤 뜸, 업데이트는 받기 요청·막는 이유 있으면 프로그램 정보 열기, 바뀐 점 보기는 깃허브 페이지 열기
- 휴대폰 `업데이트묻기검증-화면.cjs`(헤드리스 Chrome·모의 브리지) — 같은 항목, 360·412 폭 넘침 없음·단추 44px 이상, 기존 `업데이트검증-화면.cjs`는 묻는 창을 나중에로 닫고 진행
- 실제 화면 — 이고라이트(Windows), 가상기기 업데이트 시험(1.7.0 → 다음 버전)

## 구현하며 정한 것

- 처음 초점 — 다른 창처럼 맨 위 닫기에 둠
  - 묻지 않고 뜨는 창이라 회의 준비 칸에 입력하던 띄어쓰기·Enter가 업데이트를 누르면 앱이 닫힐 수 있음
  - 틀리면 — 키보드 사용자가 업데이트까지 Tab 한 번 더 누름
- 묻기 판단 시점 — 하던 화면 갱신·창 열기가 끝난 뒤(같은 차례의 작은 일로 미룸)
  - 다른 창을 여는 중에 화면 갱신이 불리면 그 창 위에 겹쳐 뜨던 문제를 막음, 시험으로 고정함
- 이번 실행에서 물은 것으로 보는 때 — 묻는 창을 띄움, 프로그램 정보를 엶, 지금 업데이트·설치를 누름
  - 프로그램 정보에서 이미 업데이트를 본 사람에게 닫은 뒤 다시 묻지 않음
- 미루는 조건
  - Windows — 녹음(권한 대기 포함), 분석, 회의 마침 흐름, 보관 저장, 지난 회의 불러오기, 설치 시작 중, 모달 창(설정·공유·고르는 창·설정 불러오기·프로그램 정보) 열림
  - 휴대폰 — 작업 중(busy), 녹음·분석(active), 의견 반영(refining), 녹음 파일 불러오기, 열린 창
- 업데이트를 누르면 묻는 창을 닫고 프로그램 정보를 연 뒤 지금 업데이트와 같은 받기를 시작함
  - 받는 정도·설치를 막는 이유·실패를 한곳에서 보이기 위함
- 릴리즈 노트 1.7.0 — 항목 8개 한도라 기존 두 항목(목록의 내 일 수, 나 고르기)을 한 항목으로 합치고 이 기능 항목을 더함
